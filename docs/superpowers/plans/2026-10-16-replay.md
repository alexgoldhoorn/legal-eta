# Replay Implementation Plan

> **Status: done 2026-10-16.** All nine tasks are implemented and merged to `main` (`7f8713b`, CI green). The checkboxes below were never ticked during execution.

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build `replay/`, an independent replayer that executes a legaleta plan as a minute-resolution activity log, judges the log against Regulation (EC) 561/2006, and reports where plan and replay disagree.

**Architecture:** A core (activity log, own regulation constants, retrospective judge, claim checks) that imports nothing from legaleta, plus one comparator module and the CLI that may use the public JSON API (`legaleta.api.plan_json`, `validate_json`). The judge recognises rests and 24 h periods by looking back over the finished log; it never carries a state machine forward.

**Tech Stack:** Python 3.12, standard library for `replay/`; pytest and Hypothesis in tests; ruff, mypy as in `pyproject.toml`.

**Spec:** `docs/superpowers/specs/2026-10-16-replay-design.md`. Contract reference: `docs/contract.md`, `docs/warnings.md`.

## Global Constraints

- `replay/` is a top-level package, not in the wheel (`[tool.hatch.build.targets.wheel] packages` stays `src/legaleta`). Run: `uv run python -m replay`.
- Core modules (`types`, `log`, `regs`, `start`, `judge_driving`, `judge_rest`, `claims`, `run`, `report`, `fuzz`) import nothing from `legaleta`. Only `compare.py` and `__main__.py` may import `legaleta`, and only `legaleta.api`. A test enforces both rules.
- The replay keeps its own copy of the regulation numbers, written from the regulation text, never imported from `src/legaleta/rules.py`.
- All durations are integer minutes; all datetimes ISO 8601 with offset; a log minute is minutes since the request `start` (prehistory is negative).
- Standard library only inside `replay/`. No network. A fixture sweep (19 routes x 3 policies) finishes in under 60 s.
- `src/` is never edited by this plan. A legaleta bug the replay finds is reported, then fixed in a separate change.
- Interpretation defaults match legaleta's documented policy: waiting and non-working stops count as rest; Guidance Note 7 restart of an overdue period at start; a regular-length rest with under 11 h inside its 24 h period counts as reduced (Art 8(2), second sentence).
- Commit style: conventional commits, trailer `Co-Authored-By: Claude Sonnet 5.5 <noreply@anthropic.com>`.

## Review Focus

1. A ferry without a sleeper cabin counts as a break, with a cabin as rest: no false violation and no missed one (Task 5 test).
2. A route across a DST change and across Monday 00:00 in `week_timezone`: days of 23 or 25 h, weeks counted in local time while the log runs on elapsed minutes (Task 5 test).
3. Adjacent blocks that together form one rest or one 15 + 30 split break (two `daily_rest` blocks back to back, a `wait` then a `break`), and zero-minute blocks (Tasks 4, 5 tests).
4. A `remaining`-form driver with negative `remaining_drive_today`, and a start state that cannot be represented as a prior log (Task 3 test).
5. A multi-week route (about 900 h) judges in linear time, not quadratic (Task 5 test with a time bound).

### Task 5: Retrospective judge, rests, compensation, ferries (Art 8, Art 9) and `judge()`

Model note: this is the design-heavy task; use the most capable model.

**Files:**
- Create: `replay/judge_rest.py`, `replay/judge.py`, `tests/replay/test_judge_rest.py`

**Interfaces:**
- Consumes: Tasks 1 to 4.
- Produces:
  - `recognise_rests(acts: list[Activity], regs: Regs, sw: Switches) -> list[RestPeriod]` (in `judge_rest.py`): merges adjacent REST activities, then classifies a merged rest by length alone (the block label is not an input): at least 2700 weekly regular; 1440 up to 2700 weekly reduced; at least 660 daily regular; 540 up to 660 daily reduced; a 180-up-to-540 rest followed in the same 24 h period by a 540-or-longer rest is a daily split pair. 24 h periods are counted back to back from each recognised daily rest end; a regular-length rest with under 660 min inside its period is `daily_reduced` when `sw.window_reduced`.
